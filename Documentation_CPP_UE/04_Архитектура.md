# 04_Архитектура

Документ содержит только подтверждённое верхнеуровневое направление. Названия модулей, классов и компонентов появятся только после отдельных решений и реализации.

## Концептуальный поток

```text
System telemetry
        ↓
normalized PC state
        ↓
world/pet state
        ↓
decision layer
        ↓
high-level action
        ↓
Unreal/C++ execution
        ↓
3D character/world
```

Схема описывает разделение ответственности, а не готовый технический контракт:

- будущие системные данные Windows преобразуются в контролируемое представление состояния ПК;
- состояние ПК рассматривается вместе с состоянием мира и питомца;
- decision layer выбирает высокоуровневое намерение и в будущем может формировать вариативную реплику;
- Unreal Engine и C++ проверяют доступность действия и отвечают за его физическое исполнение, навигацию и изменения мира;
- языковая модель не должна напрямую управлять каждым шагом персонажа или низкоуровневыми объектами движка.

Конкретные форматы данных, API, runtime и набор действий пока не определены.

## Поток работы с задачей

1. Пользователь и ChatGPT формируют TASK с явным scope.
2. Полное техническое задание помещается в БЛОК 1 файла `Documentation_CPP_UE/11_Задача_агенту.md`.
3. Агент читает task-loop и START, затем только указанные тематические и проектные документы.
4. Агент выполняет только разрешённые изменения и проверки.
5. Результат фиксируется в БЛОКЕ 2 и `TASK_HISTORY.md`.
6. После успешной задачи БЛОК 1 очищается до стандартной заглушки.
7. БЛОК 3 переводится в ожидание review пользователя / ChatGPT.

## Ограничение

До отдельной задачи нельзя выдумывать модули, классы, зависимости, систему сборки, системные API или устройство decision layer.
