# Открытые вопросы Plug_Blender

Срез после TASK 003. Для прототипа уже выбраны и проверены Blender 5.0.1, внешний MCP SDK 1.29.1, STDIO, loopback TCP, один зарегистрированный endpoint, исполнение через Blender timer и ZIP add-on. Эти ответы зафиксированы в `Documentation/02_Решения.md` и `Documentation/04_Архитектура.md`; они не являются окончательной production architecture.

Ручной сценарий обычный текстовый Codex → Astro Modeler → рабочий Blender → Cube подтверждён пользователем; TASK 003 принята. Ниже только оставшиеся вопросы. Они не блокируют выполненный Create Cube prototype и не разрешают расширять текущую TASK.

| Область | Что определить | Почему это важно |
| --- | --- | --- |
| Совместимость | Поддерживаемые Blender/Python версии и ОС сверх проверенной Windows-среды | Не обещать совместимость без тестов |
| Зависимости | Полная фиксация транзитивных версий, обновление SDK и сопровождение | Для прототипа закреплена только прямая зависимость |
| Локальная связь | Нужны ли изменения IPC и защита для нескольких пользователей ОС | Текущий localhost/token механизм рассчитан на локальный прототип |
| Controlled tools | Как проверять параметры, разрешать операции и сообщать ограничения; минимальный tool set после прототипа | Контролируемый интерфейс модели |
| Arbitrary Python | Ограничения, условия допуска и границы `execute_blender_python` | Безопасность дополнительного escape hatch |
| Scene state | Формат списка объектов и selection; active object, несколько выбранных объектов и пустое выделение | Однозначный результат чтения сцены |
| Ошибки и изменения | Error handling, частичный результат, undo/transactions | Восстановление после неудачной операции |
| Упаковка | Production release, обновление и матрица совместимости | Минимальный installable ZIP уже проверен, release pipeline не создан |
| Feedback | Механизм viewport/render feedback и screenshots | Наблюдение результата и итерационное исправление |
| Референсы | Передача изображений и чертежей, масштабы и недостающие размеры | Работа по визуальному заданию |
| Модель и API | Конкретный технический режим Astra; понадобится ли когда-либо прямой OpenAI API | Требования будущих сценариев сверх исходного направления |

Будущая TASK должна выделить только вопросы, существенно влияющие на её результат. Подтверждённые ответы затем фиксируются в решениях (`Documentation/02_Решения.md`) и соответствующих проектных документах. Предложения следующих шагов находятся в `Documentation/05_Очередь_задач.md`.
