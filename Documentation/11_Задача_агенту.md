В Edit Mode возвращается только объектный контекст.

**OUTPUT SCHEMA:**

```text
success: bool
context: null при ошибке, иначе:
  mode: string
  active_object: {name: string, type: string} | null
  selected_objects: [
    {name: string, type: string, matrix_world: number[3][4]}
  ]
  3d_cursor:
    position: number[3]
    orientation_wxyz: number[4]
message: string
```

MCP SDK публикует structured output schema с размерами векторов и матрицы. Ошибка чтения не выдаётся за пустое выделение. Полный пример — `Documentation/04_Архитектура.md`.

**ORIENTATION REPRESENTATION:** для каждого объекта возвращаются только три строки world affine matrix. Неявная четвёртая строка — `[0,0,0,1]`; столбец 3 содержит pivot, столбцы 0/1/2 — локальные X/Y/Z в мировом пространстве вместе с масштабом. Длины столбцов дают величины масштаба, нормированные ненулевые столбцы — направления осей. Отрицательный/нулевой масштаб, parenting, reflection и shear не теряются при разложении, поскольку разложения нет. При нулевой длине оси её направление не определено. Это не локальные UI channels Blender. Для Cursor выбраны мировая позиция и нормированный quaternion `[w,x,y,z]`, без Euler-дубликата.

**HEAVY GEOMETRY BEHAVIOR:** функция не обращается к `Object.data` и не читает vertices/edges/faces/normals/UV/attributes/point clouds. В реальном тесте один и тот же объект с 8 и 1 000 000 вершинами дал полностью одинаковый structured result — 589 байт при `json.dumps` в тесте, без MCP envelope. 100 выбранных объектов вернулись полностью, 12 782 байта. Объём зависит от числа выбранных объектов, а не плотности Mesh. 10-миллионный Mesh отдельно не тестировался. Локальные измерения и аналитический слой не реализованы.
