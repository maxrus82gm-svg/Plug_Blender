# Архитектура прототипа Plug_Blender / Astro Modeler

Документ описывает прототип TASK 003 и Selected Context v1 из TASK 005. Архитектура остаётся заменяемой; готовая production architecture не утверждается.

## Реализованный поток

```text
Codex MCP client
        ↓ STDIO / MCP
MCP/server.py — внешний FastMCP process
        ↓ MCP/blender_client.py — один bounded request
127.0.0.1:55881 — JSON + session token
        ↓ неблокирующий poll из bpy.app.timers
Astro Modeler — Blender main thread
        ↓ create_cube / get_selected_context
Blender Scene → новый Cube ИЛИ чтение текущего selected context
        ↓
Компактный structured result обратно в Codex
```

Codex управляет STDIO server subprocess. MCP SDK установлен во внешнем project-local Python environment. Пакет add-on `Plugins/AstroModeler/astro_modeler/` использует `bpy` и стандартную библиотеку. Модуль `bridge.py` отвечает за socket/descriptor, `__init__.py` — за lifecycle, минимальную служебную панель и операцию Blender.

## Регистрация и жизненный цикл

Start Integration привязывает loopback listener и атомарно записывает descriptor в `tempfile.gettempdir()/astro_modeler/session.json`: версия формата 1, адрес, порт и случайный token. Для изолированных тестов путь задаётся явно с обеих сторон. При занятом порте новая сессия получает ошибку; process discovery и маршрутизации нет.

Таймер с интервалом 0.05 секунды обслуживает до четырёх клиентов и не более одного вызова Blender API за tick. Socket неблокирующий; запрос ограничен 4096 байтами и пятью секундами. Ответ ограничен 1 MiB и отправляется порциями до 64 KiB за tick на клиента; превышение возвращает ошибку без усечения списка. Внутри Blender нет фоновых Python threads. Ограничения мотивированы [документацией Blender по threading](https://docs.blender.org/api/main/info_gotchas_threading.html); callback таймера подтверждён локальным API Blender и [примером timers в исходниках Blender](https://github.com/blender/blender/blob/main/doc/python_api/examples/bpy.app.timers.1.py).

Stop Integration, отключение add-on и загрузка `.blend` закрывают listener/клиентов, снимают таймер и удаляют собственный descriptor. После загрузки файла подключение требует нового Start Integration. После аварийного закрытия файл может остаться; следующий успешный запуск заменяет его. Остановка MCP сама по себе не отключает Blender listener.

## Контракт Create Cube

Публичный MCP tool `create_cube()` без аргументов сохранён. Он допускается только в Object Mode, добавляет отдельный куб размером 2 × 2 × 2 в мировом начале координат. Возвращаются `success: bool`, `object_name: string | null`, `message: string`. Blender назначает уникальное имя; повторная операция создаёт новый перекрывающийся объект.

Bridge принимает только `command=create_cube` или `command=get_selected_context` и session token. Инструментов полного Scene dump, изменения transforms, удаления, arbitrary Python или screenshots нет. OpenAI API напрямую не вызывается.

Внешний клиент ожидает ответ до пяти секунд и не делает автоматический retry: потеря ответа может означать уже выполненную операцию. Undo/transactions, гарантии exactly-once и усиленная защита между пользователями ОС не входят в этот прототип.

## Контракт Selected Context v1

`get_selected_context()` — read-only tool без аргументов. Результат содержит `success`, `context`, `message`; при ошибке `context=null`. Пример структуры с одним Empty:

```json
{
  "success": true,
  "context": {
    "mode": "OBJECT",
    "active_object": {"name": "Marker", "type": "EMPTY"},
    "selected_objects": [
      {
        "name": "Marker",
        "type": "EMPTY",
        "matrix_world": [[0, -3, 0, -4], [2, 0, 0, 6], [0, 0, 4, 2]]
      }
    ],
    "3d_cursor": {"position": [7, -3, 2.5], "orientation_wxyz": [1, 0, 0, 0]}
  },
  "message": "Selected context read."
}
```

Матрица объекта записана **строками**, 3 × 4, в мировых координатах и единицах Blender. Неявная последняя строка — `[0,0,0,1]`. Столбец 3 задаёт положение pivot, столбцы 0/1/2 — мировые векторы локальных X/Y/Z с масштабом и возможным shear/reflection. Их длины дают величины масштаба по локальным осям; нормирование ненулевого столбца даёт направление оси. У нулевого столбца направление не определено. Это мировой affine transform, не значения локальных channels из панели Blender. В примере pivot находится в `[-4,6,2]`, локальная X направлена по мировой +Y, Y — по −X, Z — по +Z, масштабы равны 2/3/4.

Отдельные Euler/quaternion/scale для объектов не возвращаются: quaternion не сохраняет shear и reflection, а матрица уже содержит нужную информацию. Значение `matrix_world` как мирового transform определено в [Blender Object API](https://docs.blender.org/api/5.0/bpy.types.Object.html#bpy.types.Object.matrix_world). Для Cursor возвращаются только мировая позиция и нормированный quaternion `[w,x,y,z]`, полученный из его матрицы с учётом текущего rotation mode; назначение cursor matrix описано в [Blender Cursor API](https://docs.blender.org/api/5.3/bpy.types.View3DCursor.html#bpy.types.View3DCursor.matrix) и проверено в установленном Blender 5.0.1.

Selected objects сортируются по имени; active возвращается отдельно как name/type либо null и может быть не выделен. Пустое выделение — успешный `selected_objects=[]`. MESH, EMPTY и другие Object types используют один общий transform-контракт без специальных данных типа. В Edit Mode возвращается объектный контекст, без чтения выбранных вершин/областей Mesh.

**Тяжёлая геометрия остаётся в Blender.** Tool не читает `Object.data`, vertices, edges, faces, normals, UV, attributes или point clouds. Объём результата зависит от числа выбранных объектов. Будущие аналитические tools должны локально считать геометрию и отдавать небольшую сводку; такие tools сейчас не создаются.

## Проверка и границы

Установленный Codex app-server обнаружил tool и создал `Cube.001` и `Cube.002` в открытом Blender 5.0.1. Имена и геометрия подтверждены из сцены и повторным чтением сохранённого `.blend`; после двух вызовов GUI process отвечал. Этот первоначальный MCP runtime test выполнялся без модельного turn. Затем пользователь подтвердил обычный текстовый Codex → MCP → Astro Modeler → рабочий Blender → Cube и принял TASK 003; это не меняет архитектурных решений прототипа.

TASK 005 проверена в отдельной GUI factory session через MCP: 8 вариантов selection и повторы, MESH/EMPTY/LIGHT, Cursor вне origin с поворотом, 100 selected objects, Mesh с 1 000 000 вершин. Последний дал тот же structured result, что Mesh с 8 вершинами: 589 байт при сериализации `json.dumps` в тесте, без MCP envelope. 20 чтений прошли проверки основного потока и неизменности context. Два чтения выполнены установленным Codex app-server без модельного turn; два вызова Create Cube сохранили рабочую регрессию.

Воспроизведение: открыть отдельный Blender с `--factory-startup --python Tests/blender_selected_runtime.py`, затем из корня репозитория запустить `.venv/Scripts/python.exe Tests/selected_runtime.py`. Скрипт создаёт только тестовую сцену, использует private descriptor/ephemeral port, сохраняет `.runtime/selected-result.json` и `.runtime/selected-context-smoke.blend`, затем закрывает тестовую сессию. Это test fixture, а не публичный выбор нескольких sessions.

Способ обычного запуска не изменился; инструкция TASK 003 — `Documentation/21_Project_Docs/ASTRO_MODELER_SETUP.md`. Для нового tool нужен пересобранный текущим `Plugins/AstroModeler/package_addon.py` ZIP и перезапуск Blender после его переустановки; имя архива остаётся `dist/astro_modeler-0.1.0.zip`. Старый уже загруженный add-on сам не обновляется. Новый selected-context tool в рабочей сессии пользователя отдельно не проверялся; проверены source fixture и установка актуального ZIP в изолированном Blender. Оставшиеся вопросы — `Documentation/03_Открытые_вопросы.md`.
