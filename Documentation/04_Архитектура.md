# Архитектурное направление Plug_Blender

Документ описывает подтверждённое направление. Он не задаёт готовую production architecture, технический контракт или структуру исходников.

## Концептуальный поток

```text
Codex / выбранная модель
        ↓
наш MCP server
        ↓
Blender integration
        ↓
Blender Python API
        ↓
Blender Scene
```

Codex выступает клиентом/host для MCP. Blender integration должна обеспечивать выполнение контролируемых операций над сценой через Blender Python API. Конкретное распределение этих ролей между addon, встроенным server и внешним process ещё не выбрано.

## Границы подтверждённого

Предпочтителен набор отдельных контролируемых tools. Доступ к произвольному Blender Python рассматривается как дополнительная возможность с ещё не определёнными ограничениями. Принцип и примеры описаны в концепции (`Documentation/21_Project_Docs/PROJECT_CONCEPT.md`).

Входное архитектурное направление не требует обязательного прямого OpenAI API из Blender. Транспорт, IPC, ports, threads, механизм исполнения в main thread, зависимости и packaging остаются открытыми вопросами (`Documentation/03_Открытые_вопросы.md`).

## Проверка направления

Первый будущий vertical prototype должен пройти цепочку **Codex → MCP → Blender → Create Cube**. После его успеха следующий тест — получение Scene Objects и Selected Object. Эти проверки ещё не выполнялись.

Реальные компоненты, контракты и source directories будут документироваться после исследования и появления подтверждающих файлов или результатов. Фактический состав репозитория описан в текущем состоянии (`Documentation/01_Текущее_состояние.md`).
