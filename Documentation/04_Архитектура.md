# Архитектура прототипа Plug_Blender / Astro Modeler

Документ описывает прототип TASK 003, Selected Context v1 из TASK 005, Geometry Placement v1 из TASK 008, Agent Feedback v1 и внутреннюю activity telemetry. Архитектура остаётся заменяемой; готовая production architecture не утверждается.

## Реализованный поток

```text
Codex MCP client
        ↓ STDIO / MCP
MCP/server.py — внешний FastMCP process
        ↓ MCP/blender_client.py — один bounded request
127.0.0.1:55881 — JSON + session token
        ↓ неблокирующий poll из bpy.app.timers
Astro Modeler — Blender main thread
        ↓ create_cube / get_selected_context / create_box_at_cursor / post_modeling_note / inspect_selected_modifier_changes
Blender Scene → новый Cube / Box ИЛИ чтение текущего selected context
        ↓
Компактный structured result обратно в Codex
```

Codex управляет STDIO server subprocess. MCP SDK установлен во внешнем project-local Python environment. Пакет add-on `Plugins/AstroModeler/astro_modeler/` использует `bpy` и стандартную библиотеку. Модуль `bridge.py` отвечает за socket/descriptor, `__init__.py` — за lifecycle, минимальную служебную панель и операцию Blender.

## Регистрация и жизненный цикл

Start Integration привязывает loopback listener и атомарно записывает descriptor в `tempfile.gettempdir()/astro_modeler/session.json`: версия формата 1, адрес, порт и случайный token. Для изолированных тестов путь задаётся явно с обеих сторон. При занятом порте новая сессия получает ошибку; process discovery и маршрутизации нет.

Таймер с интервалом 0.05 секунды обслуживает до четырёх клиентов и не более одного вызова Blender API за tick. Socket неблокирующий; запрос ограничен 4096 байтами и пятью секундами. Ответ ограничен 1 MiB и отправляется порциями до 64 KiB за tick на клиента; превышение возвращает ошибку без усечения списка. Внутри Blender нет фоновых Python threads. Ограничения мотивированы [документацией Blender по threading](https://docs.blender.org/api/main/info_gotchas_threading.html); callback таймера подтверждён локальным API Blender и [примером timers в исходниках Blender](https://github.com/blender/blender/blob/main/doc/python_api/examples/bpy.app.timers.1.py).

Stop Integration, отключение add-on и загрузка `.blend` закрывают listener/клиентов, снимают таймер и удаляют собственный descriptor. После загрузки файла подключение требует нового Start Integration. После аварийного закрытия файл может остаться; следующий успешный запуск заменяет его. Остановка MCP сама по себе не отключает Blender listener.

## Контракт Create Cube

Публичный MCP tool `create_cube()` без аргументов сохранён. Он допускается только в Object Mode, добавляет отдельный куб размером 2 × 2 × 2 в мировом начале координат. Возвращаются `success: bool`, `object_name: string | null`, `message: string`. Blender назначает уникальное имя; повторная операция создаёт новый перекрывающийся объект.

Bridge принимает пять controlled commands и session token; Box принимает три размера, note — status/summary/details, modifier inspection — без аргументов. Инструментов полного Scene dump, изменения transforms, удаления, arbitrary Python или screenshots нет. OpenAI API напрямую не вызывается.

Внешний клиент ожидает ответ до пяти секунд и не делает автоматический retry: потеря ответа может означать уже выполненную операцию. Undo/transactions, гарантии exactly-once и усиленная защита между пользователями ОС не входят в этот прототип.

## Контракт Selected Context v1

`get_selected_context()` — read-only tool без аргументов. Результат содержит `success`, `context`, `message`; при ошибке `context=null`. Пример структуры с одним Empty:

```json
{
  "success": true,
  "context": {
    "mode": "OBJECT",
    "active_object": {"name": "Marker", "type": "EMPTY"},
    "selected_objects": [
      {
        "name": "Marker",
        "type": "EMPTY",
        "matrix_world": [[0, -3, 0, -4], [2, 0, 0, 6], [0, 0, 4, 2]]
      }
    ],
    "3d_cursor": {"position": [7, -3, 2.5], "orientation_wxyz": [1, 0, 0, 0]}
  },
  "message": "Selected context read."
}
```

Матрица объекта записана **строками**, 3 × 4, в мировых координатах и единицах Blender. Неявная последняя строка — `[0,0,0,1]`. Столбец 3 задаёт положение pivot, столбцы 0/1/2 — мировые векторы локальных X/Y/Z с масштабом и возможным shear/reflection. Их длины дают величины масштаба по локальным осям; нормирование ненулевого столбца даёт направление оси. У нулевого столбца направление не определено. Это мировой affine transform, не значения локальных channels из панели Blender. В примере pivot находится в `[-4,6,2]`, локальная X направлена по мировой +Y, Y — по −X, Z — по +Z, масштабы равны 2/3/4.

Отдельные Euler/quaternion/scale для объектов не возвращаются: quaternion не сохраняет shear и reflection, а матрица уже содержит нужную информацию. Значение `matrix_world` как мирового transform определено в [Blender Object API](https://docs.blender.org/api/5.0/bpy.types.Object.html#bpy.types.Object.matrix_world). Для Cursor возвращаются только мировая позиция и нормированный quaternion `[w,x,y,z]`, полученный из его матрицы с учётом текущего rotation mode; назначение cursor matrix описано в [Blender Cursor API](https://docs.blender.org/api/5.3/bpy.types.View3DCursor.html#bpy.types.View3DCursor.matrix) и проверено в установленном Blender 5.0.1.

Selected objects сортируются по имени; active возвращается отдельно как name/type либо null и может быть не выделен. Пустое выделение — успешный `selected_objects=[]`. MESH, EMPTY и другие Object types используют один общий transform-контракт без специальных данных типа. В Edit Mode возвращается объектный контекст, без чтения выбранных вершин/областей Mesh.

**Тяжёлая геометрия остаётся в Blender.** Tool не читает `Object.data`, vertices, edges, faces, normals, UV, attributes или point clouds. Объём результата зависит от числа выбранных объектов. Будущие аналитические tools должны локально считать геометрию и отдавать небольшую сводку; такие tools сейчас не создаются.

## Контракт Geometry Placement v1

`create_box_at_cursor(size_x, size_y, size_z)` создаёт один новый Box. Все три аргумента обязательны: конечные числа строго больше нуля, в Blender units. Размеры относятся к **world X/Y/Z**, совпадающим с локальными осями нового объекта. Scene Unit Scale, mm/cm и автоматический перевод единиц не используются.

3D Cursor задаёт **только позицию** центра и origin Box. Box имеет мировую ориентацию и Object Scale `(1,1,1)`; rotation/orientation Cursor игнорируется по уточнению пользователя к TASK 008. Размеры записываются в Mesh непосредственно, без масштабирования существующих объектов. Будущая ориентация деталей через Empty / selected object / отдельный placement marker требует самостоятельного проектирования.

Положение читается из `scene.cursor.location`; определение проверено в [официальном API-коде Blender 5.0.1](https://github.com/blender/blender/blob/v5.0.1/source/blender/makesrna/intern/rna_scene.cc), фактическое размещение — в установленном GUI Blender 5.0.1. Использование Cursor quaternion для Box не требуется; контракт чтения Selected Context остаётся прежним.

Результат сохраняет компактный формат `{success: bool, object_name: string | null, message: string}` без Mesh data. Новый Box становится единственным selected и active object; прежнее выделение снимается. Cursor, геометрия и transforms прежних объектов не меняются. Object Mode обязателен. Используется текущая collection; системы выбора output/target/source нет.

Нулевые, отрицательные, non-finite и нечисловые размеры отклоняются до создания. MCP schema валидирует аргументы и может вернуть MCP validation error; client/bridge дополнительно проверяют значения, операции Blender возвращают structured failure. Положительные конечные размеры вне представимого диапазона Mesh float32 также дают явный отказ без объекта. Точность ограничена числами Blender; при ошибке создания удаляются только новые незавершённые allocations и восстанавливается прежнее выделение. Автоматического retry создающей операции нет, при потере ответа результат может быть неизвестен.

Проверено в отдельной GUI-сессии с установленным текущим ZIP: origin, ненулевая позиция, независимость от поворота Cursor, разные размеры, повторы, Scene Unit Scale 0.001 без пересчёта, отказы для invalid/non-finite/out-of-range размеров и Edit Mode. Для пяти Box проверены центр, три мировые оси, размеры Mesh и Object, Scale, normals, количество объектов, сохранность старой геометрии / transforms / Cursor и изменение selection. Один Box создан реальным установленным Codex app-server без модельного turn; сохранённые MCP settings не менялись.

Воспроизведение: отдельный GUI Blender `--factory-startup --python-exit-code 1 --python Tests/blender_box_runtime.py` с `BLENDER_USER_SCRIPTS`, `BLENDER_USER_CONFIG`, `BLENDER_USER_EXTENSIONS` в отдельных каталогах под `.runtime/`, затем `.venv/Scripts/python.exe Tests/box_runtime.py`. Fixture устанавливает `dist/astro_modeler-0.1.0.zip`, использует private descriptor и ephemeral port, проверяет lifecycle и завершает только тестовую сессию. Свидетельства: `.runtime/box-result.json`, `.runtime/codex-box-result.json`, `.runtime/box-smoke.blend`.

## Контракт Agent Feedback v1

`post_modeling_note(status, summary, details="")` передаёт технический итог Astra в существующую Sidebar-панель Astro Modeler, раздел **AGENT FEEDBACK**. Status — `OK`, `WARNING` или `BLOCKED`; summary обязателен, не пустой / не только пробельный, до 240 символов; details — строка до 1800 символов, по умолчанию пустая. Результат: `{success: bool, message: string}`. Невалидные аргументы отклоняются MCP schema или явной проверкой client/bridge.

Весь JSON request, включая command, token, поля и завершающий newline, ограничен **4096 UTF-8 bytes**. Client использует `ensure_ascii=False` и проверяет уже сериализованные байты до соединения / отправки. Лимит characters не заменяет byte check: слишком большой request получает понятный отказ. Bridge сохраняет прежний предел 4096; русские details длиннее 1000 символов проверены успешно.

Add-on хранит только runtime Python deque последних пяти notes, новая — первой; данные не записываются в Scene, properties, Text или .blend. Note не использует Blender operators и не создаёт undo step; существующий dirty-флаг сохраняется. Успешный Start очищает историю новой Integration session; load и disable также очищают её. Stop оставляет notes видимыми до следующего Start. Sidebar выводит status/summary/details с простым переносом текста по ширине; после note вызывается `tag_redraw()` для VIEW_3D areas открытых окон.

MCP server instructions требуют короткий engineering feedback после содержательной mutating modelling operation, а не внутренние рассуждения / chain-of-thought. Note также допустима по отдельной просьбе пользователя. Сама note не требует следующей note; create_cube/create_box не публикуют инженерную оценку автоматически. Здесь односторонний канал, без prompt field, scene mutation, дисковой истории или автоматического создания tools.

Переиспользованы `Tests/blender_box_runtime.py`, `Tests/box_runtime.py` и `Tests/codex_runtime.py` из TASK 008; нового GUI controller/SDK driver нет. В отдельном GUI Blender 5.0.1 с установленным ZIP проверены семь notes (одна через Codex app-server), все status, UTF-8/длинные details, rolling five, отказы, сохранность объектов/transforms/Cursor/custom properties/Text count/dirty и пустая история после save/load. Unit test проверяет ровно 4096 bytes и отказ на 4097 до открытия socket. Прежние modelling tools и Start/Stop/load/disable также проверены. Визуальную читаемость панели и обычный model-turn пользователь проверяет вручную; автоматический тест не является screenshot-review.

Ручной тест: переустановить актуальный `dist/astro_modeler-0.1.0.zip` (перезапустить Blender для загрузки нового кода), Start Integration, попросить Astra отправить тестовую MODELING NOTE и проверить её в панели. Рабочую установленную копию агент автоматически не обновляет.

## Internal Agent Activity telemetry

После успешной проверки session token и определения одной из четырёх поддерживаемых public commands Bridge вызывает внутренний activity callback. Первое событие учитывает ровно один invocation; второе фиксирует `OK` или `ERROR`. Runtime state хранит только имя tool, count, локальное время и последний outcome. Token, arguments, request/result, Selected Context и geometry не сохраняются.

Один `POST_PIXEL` draw handler показывает зелёный HUD `Astro Modeler · <tool>` в верхней центральной части 3D View в течение трёх секунд после вызова. Панель `AGENT ACTIVITY` показывает native runtime settings, last tool/result/time и counts использованных tools. Clear Statistics очищает только telemetry. Stop/Start сохраняют статистику процесса; load скрывает прежнюю activity; unregister удаляет draw handler и очищает runtime state. Данные не хранятся в Scene/`.blend`, не передаются модели и не записываются в Agent Feedback.

Activity telemetry не имеет отдельного public tool. После Modifier Inspector public MCP contract содержит пять tools.

## Modifier Parameters Inspector V1

Локальный flow `Get Modifiers → выбрать один modifier → Compare Parameters` выполняется целиком Python-кодом Blender. Target фиксирует object identity, stack index, name и type; смена объекта, порядка, имени или type делает выбор stale. Compare работает только в Object Mode, создаёт незалинкованные `__ASTRO_MODELER_TEMP_*` Mesh/Object и freshly-created modifier того же type в текущем running Blender, сравнивает user-facing RNA values exact и удаляет только созданные operation datablocks через cleanup path.

Source of truth — значения fresh modifier, а не `RNA Property.default`: probe Blender 5.0.1 подтвердил расхождения constructor state с RNA metadata. Readonly, hidden, UI/internal identifiers и unsupported RNA types исключаются или отражаются в `limitations`. Поддерживаются scalar bool/int/float/string/enum, numeric arrays и компактные ID references; embedded pointers/collections не dump-ятся. Возможный dirty `.blend` после временных datablocks принят как известное ограничение V1; add-on не сохраняет файл и не пытается сбросить flag.

Compact runtime result хранит только выбранный object/modifier, changed properties с fresh/current values и limitations. Он показывается в native `АНАЛИЗ МОДИФИКАТОРОВ`, не сохраняется в Scene/`.blend` и сбрасывается при load. Пользовательские строки секции централизованы с русским языком V1 для будущего добавления RU/EN без полноценной i18n-системы сейчас. `inspect_selected_modifier_changes()` только читает уже рассчитанный актуальный result и optional context; если Compare не выполнен или target stale, tool отказывает. AI не вычисляет diff: оно при отдельной просьбе пользователя объясняет доказанные facts по стандартной инструкции, дополняемой необязательным context, и обозначает предполагаемое намерение как вероятность. Reverse Blender→conversation transport в V1 отсутствует.

## Проверка и границы

Установленный Codex app-server обнаружил tool и создал `Cube.001` и `Cube.002` в открытом Blender 5.0.1. Имена и геометрия подтверждены из сцены и повторным чтением сохранённого `.blend`; после двух вызовов GUI process отвечал. Этот первоначальный MCP runtime test выполнялся без модельного turn. Затем пользователь подтвердил обычный текстовый Codex → MCP → Astro Modeler → рабочий Blender → Cube и принял TASK 003; это не меняет архитектурных решений прототипа.

TASK 005 проверена в отдельной GUI factory session через MCP: 8 вариантов selection и повторы, MESH/EMPTY/LIGHT, Cursor вне origin с поворотом, 100 selected objects, Mesh с 1 000 000 вершин. Последний дал тот же structured result, что Mesh с 8 вершинами: 589 байт при сериализации `json.dumps` в тесте, без MCP envelope. 20 чтений прошли проверки основного потока и неизменности context. Два чтения выполнены установленным Codex app-server без модельного turn; два вызова Create Cube сохранили рабочую регрессию.

Воспроизведение: открыть отдельный Blender с `--factory-startup --python Tests/blender_selected_runtime.py`, затем из корня репозитория запустить `.venv/Scripts/python.exe Tests/selected_runtime.py`. Скрипт создаёт только тестовую сцену, использует private descriptor/ephemeral port, сохраняет `.runtime/selected-result.json` и `.runtime/selected-context-smoke.blend`, затем закрывает тестовую сессию. Это test fixture, а не публичный выбор нескольких sessions.

Способ обычного запуска не изменился; инструкция TASK 003 — `Documentation/21_Project_Docs/ASTRO_MODELER_SETUP.md`. Для нового tool нужен пересобранный текущим `Plugins/AstroModeler/package_addon.py` ZIP и перезапуск Blender после его переустановки; имя архива остаётся `dist/astro_modeler-0.1.0.zip`. Старый уже загруженный add-on сам не обновляется. После изолированных проверок пользователь подтвердил selected-context tool в обычном текстовом диалоге с рабочим Blender; TASK 005 принята внешним INDEPENDENT REVIEW, синхронизированным в TASK 006. Подробности — `Documentation/01_Текущее_состояние.md`. Оставшиеся вопросы — `Documentation/03_Открытые_вопросы.md`.
