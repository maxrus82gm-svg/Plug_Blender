# GIT REVIEW RULES

Канонические правила Git и источника review. Репозиторий — `maxrus82gm-svg/Plug_Blender`, основная ветка — `main`.

## Контроль Git

Git контролирует пользователь. Изменение файлов по TASK не является автоматическим разрешением на изменяющие Git-действия.

Без отдельного прямого разрешения не выполняются:

- `git add`, `git commit`, `git push`, `git pull`;
- `git merge`, `git rebase`, `git reset`, `git clean`;
- `git checkout` / `git switch` с изменением состояния;
- создание, удаление и переключение веток или тегов;
- изменение индекса, remote, Git-конфигурации и переписывание истории.

Нужные для анализа и проверки read-only команды разрешены: `git status`, `git diff`, `git diff --check`, `git log`, `git branch --show-current`, `git rev-parse`, `git ls-files`, `git remote -v` и аналогичные безопасные чтения. Это не разрешает командам менять рабочие файлы, индекс, ветку или историю.

## Пользовательские изменения и scope

Перед изменением проверь доступное состояние рабочего дерева. Уже существующие незакоммиченные изменения могут принадлежать пользователю: не откатывай и не перезаписывай их. При конфликте обозначь пересечение и приостанови только зависимую часть.

При проверке сопоставь фактические изменения со scope, включая untracked-файлы и служебные настройки редактора, workspace/session state, cache и временные файлы. Перечисли посторонние изменения в UNEXPECTED CHANGES; обнаружение не разрешает их автоматически удалять или откатывать.

`git diff --check` не охватывает содержимое новых untracked-файлов. При их наличии дополнительно проверь их текст, ссылки, encoding и whitespace подходящим read-only способом. Если status/diff не проверялись, отсутствие неожиданных изменений не утверждается.

## REVIEW SOURCE

Перед содержательным review покажи, какое фактическое состояние проверяется:

```text
REVIEW SOURCE:
- repository: owner/name
- source: local working tree + uncommitted changes / local commit / remote commit
- branch/ref: подтверждённое значение
- commit: полный SHA проверяемого commit либо базового HEAD для working tree
- commit message: если подтверждено
- coverage: доступные файлы, diff и ограничения
```

Для local review базовый HEAD не содержит незакоммиченные изменения: они проверяются непосредственно в рабочем дереве, включая новые файлы. Не выдавай этот SHA за commit с результатом TASK.

Для remote review укажи реально прочитанный remote commit. Локальная настройка `origin` или локальный HEAD не доказывают текущее состояние GitHub. Если изменения из AGENT REPORT ещё не отправлены или недоступны, remote review их не подтверждает; обозначь это ограничение.

Repository, branch/ref и SHA не угадываются. Если доступны только переданные файлы или отчёт без Git-метаданных, так и укажи; проверь доступную часть без подстановки вымышленных реквизитов.

## Проверка и отчёт

Фактические файлы и результаты проверок важнее текста AGENT REPORT. Сопоставь цель, scope, файлы, содержание, релевантные проверки и ограничения. Порядок принятия и REVIEW CORRECTION определён в [START](../12_Старт_агента.md).

В разделе GIT отчёта укажи подтверждённую ветку, базовый или проверяемый commit, прочитанные status/diff и характер результата — local или remote. Отдельно сообщи, выполнял ли агент commit/push, изменял ли индекс или историю и проверял ли GitHub. Не приписывай внешнему источнику локальные изменения.
