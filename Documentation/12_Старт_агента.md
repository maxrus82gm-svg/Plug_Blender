# START — работа с TASK

Канонический источник task-loop: постановка → execution → AGENT REPORT → review. Повседневные решения и границы автономности определены в правилах агента (`Documentation/10_Правила_агента.md`).

## Маршрут чтения

Начни с текущей TASK (`Documentation/11_Задача_агенту.md`) и этого START. Для нового рабочего цикла прочитай текущее состояние (`Documentation/01_Текущее_состояние.md`) и правила агента (`Documentation/10_Правила_агента.md`). Остальное выбирай по теме и указаниям TASK; дополнительное чтение допустимо, если нужно для её решения.

| Тема | Канонический источник |
| --- | --- |
| Documentation, Markdown, перенос правил | `Documentation/20_SplitDoc/DOCUMENTATION_RULES.md` и `Documentation/20_SplitDoc/ENCODING_RULES.md` |
| Кириллица и текстовые форматы | `Documentation/20_SplitDoc/ENCODING_RULES.md` |
| Git, diff, GitHub, review | `Documentation/20_SplitDoc/GIT_REVIEW_RULES.md` |
| Предыдущие TASK и их статус | `Documentation/20_SplitDoc/TASK_HISTORY.md` |
| Назначение и ограничения продукта | `Documentation/21_Project_Docs/PROJECT_CONCEPT.md` |
| Архитектурный анализ | Решения (`Documentation/02_Решения.md`), архитектура (`Documentation/04_Архитектура.md`), открытые вопросы (`Documentation/03_Открытые_вопросы.md`) |

## Постановка и запуск

Одна `TASK XXX` по возможности является маленьким независимым законченным шагом. Большую работу делят на последовательные задачи, если это сохраняет целостность результата.

ChatGPT формирует полное задание для БЛОКА 1 файла `Documentation/11_Задача_агенту.md`: номер и название, цель, контекст, минимальное чтение, действия, scope, разрешённые и запрещённые изменения, проверки и требования к отчёту. Постоянные правила передаются ссылками.

Затем короткое стартовое сообщение указывает TASK, путь к БЛОКУ 1 и команду выполнить её. При прямой передаче полного задания пользователем в чат или вложении оно уже является основанием работы: отсутствие его копии в БЛОКЕ 1 не требует повторного разрешения. Если TASK разрешает ведение task-loop, агент фиксирует актуальное задание в БЛОКЕ 1 перед исполнением.

Дополнения до первого AGENT REPORT относятся к текущей TASK. Мелкое уточнение не требует переписывать весь БЛОК 1. Существенное изменение цели, архитектуры или scope согласуется по правилам агента (`Documentation/10_Правила_агента.md`). Передаваемые задания, уточнения и corrections оформляются цельными блоками для копирования, с пояснениями вне блока.

## Исполнение и отчёт

Агент выполняет TASK и релевантные проверки. При разрешённом обновлении документации записывает AGENT REPORT в БЛОК 2 и краткий итог в `Documentation/20_SplitDoc/TASK_HISTORY.md`. Если документационные изменения вне scope, отчёт выдаётся в чате без самовольной правки файлов.

Базовый AGENT REPORT содержит TASK, STATUS, READ, списки созданных / перенесённых / изменённых / удалённых файлов, выполненную работу, CHECKS, UNEXPECTED CHANGES, PROBLEMS, QUESTIONS, RECOMMENDED NEXT TASK, GIT и CONCLUSION. Конкретная TASK может уточнять структуру. Объём отчёта соответствует работе; непроведённые проверки обозначаются явно.

После завершения исполнения и записи отчёта БЛОК 1 очищается до трёх строк:

```text
Активной задачи на исполнение нет.
Результат предыдущей задачи ожидает review.
Следующая задача не запущена.
```

Заголовки БЛОКОВ 1–3 сохраняются по одному. БЛОК 2 содержит последний отчёт, БЛОК 3 — статус ожидания review. Это закрывает исполнение, но не означает PASS. При BLOCKED или незавершённой работе задание в БЛОКЕ 1 сохраняется с описанием препятствия.

## Review и corrections

Источник проверяемого результата и различие local / remote review оформляются по `Documentation/20_SplitDoc/GIT_REVIEW_RULES.md`. Пользователь / ChatGPT сопоставляет результат с заданием и принимает его после review. Агент не объявляет свою TASK принятой.

Недоработка внутри исходного scope оформляется как `REVIEW CORRECTION — TASK XXX`: тот же номер и название, путь `Documentation/11_Задача_агенту.md`, недостаток, требуемое исправление и необходимые проверки. БЛОК 1 заново не создаётся; correction и контекст исходной задачи задают разрешённое исправление. Агент обновляет отчёт и историю, оставляет БЛОК 1 с заглушкой и снова ожидает review.

До PASS такие corrections остаются частью той же TASK и не получают нового номера. Существенно новая работа или выход за исходный scope требуют отдельного решения и новой TASK.

Явное `TASK XXX — PASS` или однозначное принятие пользователем / ChatGPT в чате достаточно для завершения review. Обязательное дополнительное сообщение REVIEW RESULT не требуется.

## История и следующая задача

TASK_HISTORY содержит кратко: номер и название, цель, фактически сделанное, corrections и результат review. Полный AGENT REPORT и отдельный REVIEW_HISTORY туда не переносятся.

После PASS следующая TASK получает следующий номер и запускается новой постановкой. При её запуске агент синхронизирует в истории подтверждённый итог предыдущей задачи, если он ещё не записан; отдельная административная TASK для этого не нужна. Наличие следующего пункта в очереди не разрешает запускать его автоматически.
