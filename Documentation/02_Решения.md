# Решения Plug_Blender

Исходные принципы подтверждены постановкой TASK 001 от 2026-09-05. Ниже отдельно отмечены решения и проверки прототипа TASK 003; они не становятся окончательной production architecture. Оставшиеся варианты находятся в `Documentation/03_Открытые_вопросы.md`.

## 2026-09-05 — Память проекта

`Documentation/` является активной памятью Plug_Blender. Постоянные пути переносимы и задаются относительно корня репозитория; правила записи путей и единственного канонического источника находятся в `Documentation/20_SplitDoc/DOCUMENTATION_RULES.md`.

История Plug_Blender начинается с `TASK 001 — Bootstrap документации Plug_Blender`. Заимствование универсального шаблона не переносит историю другого проекта.

## 2026-09-05 — Назначение и исполнительный API

Проект предназначен для AI-assisted Blender modelling. AI должен ускорять работу 3D-моделлера, создавать и изменять геометрию через Blender Python API; пользователь может продолжать ручную доработку результата.

## 2026-09-05 — Codex и MCP

Codex поддерживает MCP servers, поэтому Codex как клиент/host → наш MCP server → Blender integration является подтверждённым допустимым и предпочтительным направлением. В TASK 003 оно проверено через MCP-клиент установленного Codex app-server и реальный открытый Blender.

Прямой OpenAI API не считается обязательной частью архитектуры. Для TASK 003 выбран локальный вариант связи, описанный ниже.

## 2026-09-05 — Контролируемые инструменты

Основные операции предпочтительно предоставлять модели отдельными контролируемыми tools. Произвольный `execute_blender_python` допускается как дополнительный escape hatch; он не становится автоматически единственным интерфейсом. Концептуальные примеры и границы — в `Documentation/21_Project_Docs/PROJECT_CONCEPT.md`.

## 2026-09-05 — Последовательные технические этапы

Первый технический milestone — **Codex → MCP → Blender → Create Cube**. Следующий тест после его успеха — **Scene Objects + Selected Object**: получить список объектов сцены и определить текущий selected object.

Архитектурные решения принимаются отдельными проверяемыми этапами после исследования и реального прототипа. Большая универсальная modelling system на старте не строится. Create Cube реализован и проверен в TASK 003; следующий технический этап не запущен.

## 2026-09-05 — Astro Modeler, решения TASK 003

Пользовательское название add-on — **Astro Modeler**, пакет — `Plugins/AstroModeler/astro_modeler/`. Отдельный внешний MCP process находится в `MCP/`; тесты — в `Tests/`. Корневой AGENTS.md остаётся точкой входа документации.

Выбран **STDIO Codex ↔ внешний FastMCP server ↔ loopback TCP ↔ add-on**. STDIO позволяет Codex управлять жизненным циклом MCP subprocess без отдельного HTTP-сервиса. Внешний SDK сохраняет Blender package независимым от сторонних pip-пакетов. Небольшой TCP bridge требует только стандартной библиотеки; embedded MCP и HTTP добавили бы прототипу зависимости или обслуживание, не нужные для одной операции.

Blender обслуживает неблокирующий socket через `bpy.app.timers`, включая сам вызов `bpy` в основном потоке. Долгоживущих Python threads внутри add-on нет. Внешний MCP process может ожидать ответ, не блокируя Blender UI.

Одна сессия явно подключается через Start Integration. Адрес `127.0.0.1:55881` фиксирован для прототипа; exclusive bind исключает вторую зарегистрированную сессию. Descriptor во временном каталоге ОС содержит endpoint и случайный token текущего подключения. Поиска процессов и выбора нескольких сессий нет.

Публичный tool только `create_cube()` без аргументов. Ключи результата — `success`, `object_name`, `message`. Повтор не идемпотентен: при неопределённом результате клиент не повторяет запрос автоматически. Другие tools и произвольный Python не реализованы.

Прямая внешняя зависимость — официальный `mcp==1.29.1`, установленный в проектную `.venv/`. Проверены Windows, Blender 5.0.1 и внешний Python 3.13.8. ZIP-пакет без зависимостей установлен и включён в изолированном Blender окружении. Эти версии определяют проверенную среду, а не обещание совместимости со всеми платформами.

Прототип доказан двумя вызовами установленного Codex app-server в GUI Blender и независимой проверкой сохранённой сцены. Тест выполнялся без модельного turn и без изменения сохранённой MCP-конфигурации; подключение обычного диалога описано в `Documentation/21_Project_Docs/ASTRO_MODELER_SETUP.md`.
