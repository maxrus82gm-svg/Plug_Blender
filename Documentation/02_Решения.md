# Решения Plug_Blender

Записи ниже подтверждены постановкой TASK 001 от 2026-09-05. Их статус — **принято как направление или принцип**, а не «реализовано». Технические варианты до выбора остаются в открытых вопросах (`Documentation/03_Открытые_вопросы.md`).

## 2026-09-05 — Память проекта

`Documentation/` является активной памятью Plug_Blender. Постоянные пути переносимы и задаются относительно корня репозитория; правила записи путей и единственного канонического источника находятся в `Documentation/20_SplitDoc/DOCUMENTATION_RULES.md`.

История Plug_Blender начинается с `TASK 001 — Bootstrap документации Plug_Blender`. Заимствование универсального шаблона не переносит историю другого проекта.

## 2026-09-05 — Назначение и исполнительный API

Проект предназначен для AI-assisted Blender modelling. AI должен ускорять работу 3D-моделлера, создавать и изменять геометрию через Blender Python API; пользователь может продолжать ручную доработку результата.

## 2026-09-05 — Codex и MCP

Codex поддерживает MCP servers, поэтому Codex как клиент/host → наш MCP server → Blender integration является подтверждённым допустимым и предпочтительным направлением. Это исходный факт постановки TASK 001; подключение в репозитории ещё не проверено.

Прямой OpenAI API не считается обязательной частью архитектуры. Устройство связи MCP ↔ Blender пока не выбрано.

## 2026-09-05 — Контролируемые инструменты

Основные операции предпочтительно предоставлять модели отдельными контролируемыми tools. Произвольный `execute_blender_python` допускается как дополнительный escape hatch; он не становится автоматически единственным интерфейсом. Концептуальные примеры и границы — в `Documentation/21_Project_Docs/PROJECT_CONCEPT.md`.

## 2026-09-05 — Последовательные технические этапы

Первый технический milestone — **Codex → MCP → Blender → Create Cube**. Следующий тест после его успеха — **Scene Objects + Selected Object**: получить список объектов сцены и определить текущий selected object.

Архитектурные решения принимаются отдельными проверяемыми этапами после исследования и реального прототипа. Большая универсальная modelling system на старте не строится. Эти этапы являются будущей работой; TASK 001 создаёт документационную основу.
